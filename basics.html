変数と代入｜今の値を覚える

変数は、数などの値に付ける名前です。代入は、その名前で覚えている値を入れ替えること。

x = 3
今の値は3
→
x = x + 1
右側の3 + 1を計算
→
今のxは4

=は代入、==は「等しいか」の判定です。nも変数名のひとつで、円盤の枚数などを表します。3nは数学では3×n。Pythonでは3 * nと書きます。

自分で確かめる

n = 4のとき、n = n + 2を実行した後のnと、3 * nはいくつ？

答えと理由を見る

nは6、3 * nは18です。右側を古い値で計算してから入れ直します。

条件分岐と繰り返し｜いつ・何回するか

条件分岐は「条件に合うときだけ実行する」こと。繰り返しは、同じ手順を何度も実行することです。

1total = 02for x in range(1, 5):3    if x % 2 == 0:4        total = total + x

forは順番に値を取り出して繰り返します。range(1, 5)は1、2、3、4。最後の5は含みません。ifは条件の判定。%は割り算の余りなので、x % 2 == 0は「xが偶数」を表します。

字下げ（インデント）は処理のまとまりです。上の例では4行目だけが、偶数のときに実行されます。whileは条件が成り立つ間、繰り返す命令です。

自分で確かめる

上のコードが終わったとき、totalはいくつ？　足されなかったxも書いてみよう。

答えと理由を見る

2と4が足されて6です。1と3のときは条件に合わないので、totalは変わりません。

配列と添字｜場所の番号と中身を分ける

配列は、値を順番に並べて扱う仕組みです。添字（そえじ）は、その場所を指定する番号。この教材では0から数えます。

score = [2, 0, 3, 2, 1]
添字：人の番号01234
値：その人の得点20321

score[3]は「番号3の場所の値」なので2です。得点を数える別の配列countでは、添字は得点、値は人数を表します。

2点の人を読む
→
count[2]を1増やす

累積は、順に足し合わせること。「2点以上の人数」は「3点以上の人数＋ちょうど2点の人数」です。安定な並べ替えは、同じ値の人の元の順番を保ちます。

自分で確かめる

score[2]はいくつ？　2点の人は何人？

答えと理由を見る

score[2]は3。2点の人は番号0と3の2人です。「場所が2」と「値が2」を区別しましょう。

スタックとDUP｜一番上だけを操作する

スタックは、積み重ねたお皿のように、一番上から入れて、一番上から取り出す仕組みです。

DUP（デュープ）は、英語のduplicate（複製する）に由来する命令名。一番上と同じ数を、もう1個上に積みます。この問題では、元の数は消えません。

＋は、上の2個を取り出して足し、その結果を1個積みます。DUPはスタック全体のコピーではありません。Pythonのリストでは、appendが末尾に追加、pop()が末尾を取り出す操作です。[-1]は末尾の値を読みます。

自分で確かめる

下から3、5と積まれているとき、DUPの後はどうなる？　続けて＋を実行すると？

答えと理由を見る

DUP後は下から[3, 5, 5]。＋の後は[3, 10]です。底の3は動かず、一番上の数だけを複製します。

再帰と停止条件｜小さな同じ仕事に頼む

再帰は、関数が自分と同じ関数を呼び出すことです。ハノイの塔なら「3枚を移す」を「2枚を移す」仕事に分けます。

停止条件は、もう小さな仕事を呼ばずに終わる条件。総合編では「1枚になったら直接動かす」です。毎回枚数を1減らし、この条件へ近づけます。年度別解説では原題に合わせ「0枚なら何もしない」を使います。

自分で確かめる

呼び出すときに枚数nを減らさないと、なぜ困る？

答えと理由を見る

同じ大きさの仕事を何度も呼び、停止条件に近づきません。「止まる条件」と「そこへ近づく変化」の両方が必要です。

商と余り｜次の計算を決める情報

整数の割り算では、商と余りを分けて考えます。Pythonの // は整数の商、% は余りです。

14 ÷ 6
→
商2、余り2
14 = 6 × 2 + 2

小数の筆算は「余りを10倍して、もう一度割る」の繰り返しです。1÷6では、余り1→4→4…となります。同じ余りに戻ると、それ以降の計算も同じになります。

今の余り10倍して割る次の桁次の余り
110÷614
440÷664

辞書は、キーと値を対応させて記録する仕組み。小数の問題では「余り→初めて出た位置」を記録します。

自分で確かめる

「同じ桁が出た」だけで循環を決めてよい？

答えと理由を見る

決められません。次の計算を決めるのは余りです。余りが同じなら、次の桁と次の余りも同じになります。

最小・下限・反例｜答えに理由を付ける

「6分で終わる方法がある」と「6分が最短」は、示すことが違います。最短と言うには、もっと早くできない理由も必要です。

下限
これ未満は不可能
→
実現する方法
その時間で終わる
→
両方が同じ値
最短と分かる

合計18分の仕事を3台で処理するなら、少なくとも18÷3＝6分。これが下限です。実際に6分で終わる割り当ても作れれば、最短といえます。

貪欲法は、その時点でよさそうな選択を繰り返す方法。仕事の問題では「今、最も空いている機械」に入れます。必ず最短とは限りません。反例は「いつでも正しい」という主張が成立しない具体例です。

発展で出てくるOPTは最良の値、Tはある手順で得た値。「T ≤ (5/3)OPT」は、結果が最良の5/3倍以内という近似の保証を表します。

自分で確かめる

3台への割り当てで、6分で終わる例を1つ見つけた。それだけで最短と言える？

答えと理由を見る

まだ言えません。6分未満では終えられない理由も必要です。3台が6分未満ずつ働いても、合計は18分未満。合計18分の仕事を終えるには足りません。
